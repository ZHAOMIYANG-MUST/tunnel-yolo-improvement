## 实验②-A：CBAM 注意力（结果：**无效，未采纳**）

**动机**：隧道内光照不均、水渍与衬砌背景对比度低，电缆、接缝等纹理容易造成误检（对应调研报告"暗"这一痛点）。CBAM 通过通道+空间双注意力让网络把响应集中到病害区域。

**结构改动**（`configs/yolov8n-cbam.yaml`）：在颈部三个检测分支的输出特征上各插入 1 个 CBAM（层 17/21/25），并在主干末端 SPPF 之后加 1 个 CBAM（层 10），共 4 处：

| 位置 | 层号 | 通道 | 参数量 |
|---|---|---|---|
| 主干末端（SPPF 后） | 10 | 256 | 8,290 |
| P3 检测分支 | 17 | 64 | 1,122 |
| P4 检测分支 | 21 | 128 | 2,146 |
| P5 检测分支 | 25 | 256 | 8,290 |
| **合计** | | | **19,848** |

**结构一致性验证**（`scripts/_diag_arch.py`）：逐层对比官方 YOLOv8n 与改进结构的参数量，除 4 个 CBAM 层外**逐层完全一致**，总参数量差 19,848 = CBAM 参数之和。这证明消融的"唯一变量"确实是注意力模块本身。

**权重迁移**（`scripts/make_init_weights.py`）：插入 CBAM 会使后续层号整体后移，权重按 `model.<层号>.<参数名>` 命名，因此按映射表做了层号重映射；迁移 367/367 项（其中 CBAM 与检测头类别分支为新初始化，与基线加载 COCO 权重的方式一致）。

**训练与结果**：2 轮冒烟测试通过（mAP50 = 0.766，同期 WIoU 单独训练为 0.713，开局看着不错）；正式训练 273 轮（早停触发，best 出现在第 138 轮），产物 `runs/detect/runs/imp2_cbam/`。

结果与 WIoU 单版对比（测试集）：

| 指标 | WIoU 单版 | + CBAM | 变化 |
|---|---|---|---|
| P | 0.934 | 0.921 | **−1.3** |
| R | 0.924 | 0.933 | +0.9 |
| mAP50 | 0.959 | 0.953 | **−0.6** |
| mAP50-95 | 0.740 | 0.727 | **−1.3** |

**结论：四项指标三降一升，mAP50 与 mAP50-95 均下降，判定为无效改进，不纳入最终模型。**

**原因分析**（三条，均可写进论文讨论）：

1. **形态不匹配**：CBAM 的空间注意力用 7×7 方形卷积生成空间权重，感受野各向同性；而本数据集的渗漏是"纵向贯穿长条"（23% 的框高度≈1.0），方形感受野无法有效刻画细长结构，反而可能削弱其边缘响应。
2. **场景过于稀疏，注意力无从发挥**：统计显示 85% 的图片只含 1 个目标、70.8% 是大目标。注意力的价值在于"从复杂背景中筛出目标"，本数据集既没有密集小目标、也没有强干扰背景，因此增益空间本就有限。这一点在冒烟阶段（前 2 轮）表现为"领先"，但在 300 轮的充分收敛后反而落后——说明 CBAM 只是加快了早期收敛，并未提升收敛上限（best 轮次从 175 提前到 138 亦是佐证）。
3. **可能与 WIoU v3 的功能重叠**：WIoU 的动态聚焦已经在抑制"不确定样本"的梯度，注意力再对特征做重新加权，两者叠加时对困难样本的处理存在相互干扰的可能。

> 这个负结果本身是有价值的论文素材：它说明在隧道渗漏这种"稀疏大目标 + 细长形态"的场景下，通用注意力模块（CBAM）并不适用，需要**形状感知**的注意力设计——这正好引出实验②-B。

## 实验②-B：坐标注意力 CA（Coordinate Attention, CVPR 2021）

**动机**（由实验②-A 的失败直接导出）：CBAM 的方形空间感受野不适合细长目标，因此改用 CA——它把特征沿**高度**和**宽度**两个方向分别做一维池化，得到两组带方向信息的位置编码，再各自生成方向感知的注意力权重。纵向贯穿的渗漏条带与横向裂缝都能被显式建模，与数据分析报告的形态统计（23% 框高度≈1.0、高中位数 0.75）严格对应。

**结构改动**（`configs/yolov8n-ca.yaml`）：插入位置与 CBAM 版**完全一致**（层 10/17/21/25，主干末端 + 颈部三个检测分支），仅替换模块类型，保证两组实验"唯一变量 = 注意力模块类型"，可直接对比。

| 位置 | 层号 | 通道 | 参数量 |
|---|---|---|---|
| 主干末端（SPPF 后） | 10 | 256 | 6,680 |
| P3 检测分支 | 17 | 64 | 1,688 |
| P4 检测分支 | 21 | 128 | 3,352 |
| P5 检测分支 | 25 | 256 | 6,680 |
| **合计** | | | **18,400**（3,011,043 → 3,029,443，+0.61%） |

**实现**：`plugins/coordatt.py`；注册方式与 CBAM 走同一套机制（`plugins/__init__.py` 统一注册，`run_improved.py` 作为唯一入口）。
**权重迁移**：`python scripts/make_init_weights.py --cfg configs/yolov8n-ca.yaml --out weights/yolov8n-ca-init.pt` → 迁移 319/399 项，**主干+颈部全部迁移，未迁移 0 项**（仅检测头类别分支与 44 项新增 CA 参数为新初始化），与基线初始化条件一致。

**进展**：训练 300 轮完成（best 在第 195 轮附近），测试评估 `runs/detect/runs/imp2b_ca_test/`。

**结果与结论**（测试集，对比 WIoU 单版）：

| 指标 | WIoU 单版 | + CA | 变化 |
|---|---|---|---|
| P | 0.934 | **0.948** | +1.4 |
| R | 0.924 | 0.898 | **−2.6** |
| mAP50 | 0.959 | 0.945 | **−1.4** |
| mAP50-95 | 0.740 | 0.728 | **−1.2** |

CA 把模型推向"更保守"——Precision 涨到全场最高，但 Recall 大幅下降（漏检增多），总体 mAP 仍低于 WIoU 单版。**判定无效，未采纳。**

**两次注意力实验（CBAM、CA）均失败，结论：在本数据集上注意力机制不适用。** 核心原因（与数据分析相互印证）：85% 的图片仅含 1 个目标、70.8% 为大目标——注意力机制的设计目标是"在复杂/密集场景中筛选目标特征"，本数据集不存在这类需求；同时渗漏与背景纹理在特征上差异较大（否则基线 Recall 不会那么高），可挖掘的判别信息有限。CBAM 提速不提上限、CA 牺牲召回换精度，两种失败模式都印证了这一点。

> **对论文的意义**：这两个负结果是"消融讨论"章节的优质素材——系统验证了通用注意力在此场景无效，反衬 WIoU 的有效性不是随机涨点；也直接支撑了下一项改进的选择依据（从"空间注意力"转向"多尺度融合/形状感知"）。

## 对比结论（实验 #2）

- **mAP50：测试集 +3.0 个点**（0.929 → 0.959），验证集 +1.5 个点（0.947 → 0.962）
- **Precision：测试集 +6.3 个点**（0.871 → 0.934）——误检大幅减少，与"细长水渍与背景纹理易混淆"的痛点吻合
- **mAP50-95：测试集 +1.7 个点**（0.723 → 0.740）——框的定位质量提升，说明细长目标回归更准，验证了数据分析报告的改进动机（38.9% 病态长宽比目标）
- Recall 基本持平（-0.4），无副作用
- 参数量/速度零开销（损失函数改进不引入计算）
- **结论：WIoU v3 有效，保留，作为后续实验的叠加基础**

## 实现说明

### 实验①（WIoU v3 损失）

- 实现：修改 `ultralytics/utils/loss.py`（原文件备份 `docs/patches/backup/loss.py.orig`），环境变量 `YOLO_IOU_TYPE=wiou` 启用，默认关闭
- WIoU v3：Tong et al., *An Efficient IoU-Based Loss for Auxiliary Bounding Box Regression*, arXiv:2301.10051；R_WIoU = exp(ρ²/(W_g²+H_g²))（分母 detach），聚焦系数 r = β/(δ·α^(β−δ))，β 为离群度（L_IoU 对其 EMA 均值之比，momentum=0.1），α=1.9，δ=3
- 复现命令：`PYTHONIOENCODING=utf-8 YOLO_IOU_TYPE=wiou yolo detect train data=configs/tunnel.yaml model=yolov8n.pt epochs=300 imgsz=640 batch=16 device=0 workers=4 seed=42 project=runs name=imp1_wiou exist_ok=True`
- 产物：`runs/detect/runs/imp1_wiou/`（训练曲线、results.csv、权重），测试评估 `runs/detect/runs/imp1_wiou_test/`

### 实验②（CBAM 注意力）

- 自定义模块：`plugins/cbam.py`（`CBAM` = 通道注意力 + 空间注意力，ECCV 2018 原版实现）；`plugins/__init__.py` 把它注册进 `ultralytics.nn.tasks`，使模型 yaml 与权重文件都能被正常解析
- 统一入口：`run_improved.py`（`yolo` 命令行无法识别自定义模块，必须经此入口构建/加载模型）
- 生成初始化权重：`python scripts/make_init_weights.py` → `weights/yolov8n-cbam-init.pt`
- 结构校验：`python scripts/_diag_arch.py`
- 复现命令：
  ```
  PYTHONIOENCODING=utf-8 YOLO_IOU_TYPE=wiou python run_improved.py train \
      model=weights/yolov8n-cbam-init.pt data=configs/tunnel.yaml \
      epochs=300 imgsz=640 batch=16 device=0 workers=4 seed=42 project=runs name=imp2_cbam exist_ok=True
  ```
- 注意：CBAM 层的 yaml 里写的是**缩放后**的通道数（16/32/64/128/256），因为 CBAM 不在 ultralytics 的 `base_modules` 白名单里，其参数不会被 width 缩放；本文件因此把 depth/width 固定为 1.0 并直接写实际值，与官方 yolov8n 等价（已由 `_diag_arch.py` 逐层验证）
